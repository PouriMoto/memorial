# روند بررسی و انتشار

این سند توضیح می‌دهد محتوای تازه (به‌ویژه خاطره‌ها و تصویرها) چگونه بررسی و منتشر می‌شود. سایت ایستا است؛ پس انتشار یعنی تغییر در فایل‌های محتوا و ساخت دوبارهٔ سایت.

## ۱. دریافت خاطره

- خاطره‌ها از طریق فرم گوگل (`googleFormsUrl` در `settings.json`) یا کانال تماس جمع می‌شوند.
- فرم گوگل با پرسش آپلود فایل معمولاً از پاسخ‌دهنده می‌خواهد وارد حساب گوگل شود؛ بنابراین ارسال فایل ناشناس تضمین نمی‌شود.
- **پاسخ‌های خام فرم و اطلاعات تماس هرگز در مخزن گذاشته نمی‌شوند.** آن‌ها فقط در Google Forms/Sheets یا جای خصوصی خودتان می‌مانند.

## ۲. بررسی سردبیری

1. متن را بخوانید: اتهام بی‌منبع، اطلاعات خصوصی دیگران، نقل‌قول جعلی یا محتوای توهین‌آمیز نباید باشد.
2. ادعاهای تاریخی را در صورت امکان با منابع بسنجید؛ در غیر این صورت متن به‌عنوان «روایت شخصی» منتشر می‌شود و حقیقت تاریخی تلقی نمی‌شود.
3. ویرایش اندک (غلط‌گیری) با اطلاع نویسنده؛ تغییر محتوایی فقط با موافقت او.

## ۳. بررسی اجازهٔ انتشار

- اجازهٔ صریح نویسنده (ایمیل، پیام یا گزینهٔ فرم) را بگیرید و در جای خصوصی نگه دارید.
- اگر خاطره دربارهٔ دیگران اطلاعات خصوصی دارد، آن بخش را حذف کنید.
- بدون اجازه: `publicationPermission` را `not-granted` یا `unknown` بگذارید؛ خاطره منتشر نمی‌شود.

## ۴. تأیید و انتشار

در `memories.json` آیتم را اضافه کنید یا تغییر دهید:

```json
{
  "id": "m-001",
  "displayName": "نام نمایشی",
  "relationship": "دوست",
  "text": "متن خاطره…",
  "date": "1999-05",
  "reviewStatus": "approved",
  "publicationPermission": "granted"
}
```

فقط وقتی هر دو مقدار `approved` و `granted` باشند در سایت نمایش داده می‌شود. سپس:

```bash
npm test          # اعتبارسنجی محتوا، بررسی نوع، ساخت، بررسی لینک
git add -A && git commit -m "Add approved memory m-001"
git push          # workflow استقرار اجرا می‌شود
```

## ۵. تصویرها و ویدیوها

- پیش از افزودن، منبع و مجوز را ثبت کنید (`creator`, `sourceUrl`, `license`, `licenseUrl`).
- مجوزهایی که انتشار مجدد را اجازه نمی‌دهند (مثلاً «همهٔ حقوق محفوظ») بدون اجازهٔ کتبی منتشر نشوند.
- ویدیو را روی آپارات/یوتیوب میزبانی کنید و فقط پیوند را بگذارید. فایل ویدیو در مخزن گذاشته نمی‌شود.

## ۶. حذف

اگر نویسنده یا صاحب حق درخواست حذف کند، آیتم را از فایل JSON پاک کنید (برای تصویر، فایل را هم از `public/images/` حذف کنید) و دوباره منتشر کنید. به یاد داشته باشید که تاریخچهٔ git هنوز آن را نگه می‌دارد؛ برای حذف قطعی لازم است تاریخچه هم پاک‌سازی شود.
